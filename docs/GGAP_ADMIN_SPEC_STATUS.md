## 4. 必須先釐清的差異

### F01：可進入頁面與保留程式不一致

目前財務主選單是三類對帳、差異處理及異動紀錄。結算批次、結算單、手動調整、部分財務設定與審核頁的舊入口已轉往對帳、精度設定或停用說明。

前一批對保留結算頁做的精度修正，**不能當成「目前總後台已開放完整結算模組」的證據**。本輪不擅自恢復這些入口。參見 [舊入口映射](C:/Users/user/Desktop/ggap/src/router/modules/navigation.ts:358)。

### F02：幣別精度與結算精度是兩份設定

目前可進入的 /platform/currencies/precision 更新 currencies[].decimalPlaces／minimumUnit；
結算格式／計算使用 settlementRule.amountPrecision。後者的原設定頁保留程式，但原路由已映射走。應先核准兩者的適用範圍與優先序，而非直接合併數值。

- 可進入的對帳、差異、人員權限、幣別、語系、系統紀錄及匯率歷史存在僅顯示訊息的匯出入口，逐頁表已標出。

### F04：帳號／權限管理與真正執行端尚未閉合

管理頁可修改本地帳號、角色與敏感授權，但演示登入仍由 auth.ts 的固定帳號決定；報表部分讀取權限 Store，不代表所有頁面、按鈕與資料查詢均已接入。正式授權需在伺服器強制執行，不能只靠藏按鈕。

### F05：全域設定需要「消費端對照」

平台預設語系、使用者介面語言、報表時區、幣別精度、結算精度、維護頁與基本設定中的維護項目並非同一設定。必須定義誰控制哪一頁及哪種資料；不能籠統寫成「全部依全域設定」。

### F06：既有規格不是目前可直接凍結的定稿

歷史文件引用其他路徑／批次與本專案不存在的 GGAP_PRD_v2.2_THREE_PORTALS.md；亦含舊的「頁首顯示開發演示」要求，已被後續使用者要求取代。這不代表所有歷史內容失效，而是每項需重新確認其適用範圍。代理詳情仍直接顯示結算公式未定案，不能自行推定合約公式。

## 5. 權限與全域設定驗收共通規則（候選）

所有頁面套用以下候選條件；沒有對應證據就仍是待驗收。

- **P0 入口**：總後台 R_SUPER／R_ADMIN 可依核准矩陣進入；代理與商戶角色不得直接以網址越權。這不等於 R_ADMIN 可以做所有操作。
- **P1 動作**：查看、新增、修改、停用、匯出、確認／覆核、敏感資料、憑證操作分開授權；禁用按鈕以外，資料處理端也必須拒絕。
- **P2 資料範圍**：同一查詢、詳情、下鑽和匯出使用同一授權範圍；跨商戶／代理資料不得因 ID 猜測洩露。
- **P3 稽核**：寫入記錄操作人、對象、前後值、時間／時區、原因和關聯請求；正式端防竄改與保存期限待定。
- **G1 表格**：密度、邊框、斑馬紋、表頭、排序與分頁有共用規則；內嵌表格例外必須記錄，不機械替換。
- **G2 金額**：明列交易幣、結算幣、精度來源、捨入時機／方式及歷史快照，不由格式化函式猜商務規則。
- **G3 日期**：儲存時區、展示時區、日界與查詢含迄規則分開；日期格式／平台預設與個人偏好定義優先序。
- **G4 介面**：圓角、深淺色、語系、鍵盤焦點、窄螢幕；入口隱藏與功能停用分開。
- **G5 失敗**：loading／empty／error／無權限／不存在資料，以及防重送、重試、部分成功、版本衝突都必須驗收。
- **G6 匯出**：真實檔案、同查詢範圍、同權限、正確金額／日期、編碼、欄位清單、下載失敗；不能以 toast 成功代替驗收。

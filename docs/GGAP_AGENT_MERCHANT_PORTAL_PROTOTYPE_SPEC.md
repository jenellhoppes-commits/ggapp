# GGAP 代理後台與商戶後台原型規格

版本：PORTAL-PROTOTYPE v0.1｜日期：2026-09-07｜狀態：原型執行稿，待使用者看過完整原型後定案

本文件用於先完成可操作原型及規格核實。畫面文字、資訊架構與互動可先依本稿製作；佣金、收入、成本、應收應付、匯率及正式帳務結果若缺少已核准來源或公式，一律顯示「待核對／缺少來源」，不得自行套用舊公式。原型通過內部核實後，再由使用者確認為正式規格。

## 1. 共同原則

### 1.1 角色與資料範圍

| 入口 | 角色 | 資料範圍 | 預設首頁 |
| --- | --- | --- | --- |
| 代理後台 | `AGENT` | 自己、下級代理及其所屬商戶資料；不得跨代理樹 | `/agent/dashboard` |
| 商戶後台 | `MERCHANT` | 自身商戶、幣別線、授權遊戲、會員、注單、流水、帳單與串接資料 | `/merchant/dashboard` |

- 登入角色與入口不符時顯示 403，不自動切換成其他角色。
- 前端隱藏無權限項目，服務端仍需依登入身分限制資料。
- 清單、摘要、匯出及詳情必須使用同一資料範圍。
- 代理不可看其他代理樹；商戶不得用網址參數切換到其他商戶。

### 1.2 共用頁面結構

1. 左側使用「分區標題＋平列功能」，不使用多層展開樹。
2. 頁首包含標題、用途說明、目前角色／商戶或代理名稱；右側最多一個主要動作。
3. 一般列表使用 2–4 個常用條件，其餘放「更多條件」。固定提供查詢與重置，Enter 可送出。
4. KPI 卡片只放儀錶板與報表；一般列表最多一行必要摘要。
5. 列表第一眼保留 5–7 個資料群組。完整識別、歷史、來源及技術內容放詳情抽屜。
6. 每列保留「查看」或最高頻操作；低頻操作放有文字標籤的更多選單。
7. 返回清單要保留查詢、分頁、分頁筆數及捲動位置。

### 1.3 共用頂部列與帳號選單

代理後台與商戶後台依使用者提供的畫面（`docs/references/portal-user-menu-reference.png`），使用同一套頂部列與右上角帳號選單。桌面由左至右呈現：選單開關、目前環境、待處理事項、站內搜尋、通知、使用者頭像。沒有資料來源的待處理數量或通知不得顯示假數字。

| 項目 | 呈現與行為 |
| --- | --- |
| 環境 | 膠囊標籤顯示正式／測試／Sandbox；不可由一般使用者任意切換 |
| 待處理 | 顯示目前角色真正可處理的數量；代理可連到商戶草稿／對帳，商戶可連到串接缺項／帳單差異 |
| 搜尋 | 搜尋目前入口的功能與可到達頁面；桌面顯示輸入框與快捷鍵提示，手機改為圖示開啟 |
| 通知 | 顯示未讀狀態；點擊後使用抽屜或選單，不跳到其他角色資料 |
| 頭像 | 圓形頭像按鈕；有可讀名稱、鍵盤焦點、展開狀態與點擊外部關閉 |

帳號選單寬度約 280–320 px，依附在頭像下方，保持清楚留白與分隔線：

1. 頂部顯示頭像、使用者名稱、登入帳號／Email 與角色名稱；過長文字省略但可查看完整值。
2. 「帳號與權限」開啟自身帳號、角色及資料範圍摘要。代理／商戶只能查看自己的權限，不在此管理其他帳號或角色。
3. 「顯示偏好」區包含切換深色／淺色模式、全螢幕顯示及介面語言。
4. 深淺模式切換後立即套用並保留偏好；不重置目前頁面條件。
5. 全螢幕在瀏覽器不支援或手機環境時隱藏或停用並說明原因。
6. 介面語言預設繁體中文；語言下拉選單需有可讀標籤，不只顯示國旗或圖示。
7. 最下方以紅色文字呈現「登出」。若頁面有未儲存資料，先進入共用未儲存提醒；否則結束登入並回到該入口登入頁。
8. 桌面可用 Escape 關閉並把焦點送回頭像；手機改為不超出螢幕的底部面板或全寬選單。

### 1.4 共用組件

原型優先沿用或整理現有元件，不在每頁重做同一套樣式。

| 組件 | 必要能力 |
| --- | --- |
| `PortalHeaderBar` | 環境、待處理、搜尋、通知與使用者選單；桌面／手機呈現一致 |
| `PortalUserMenu` | 使用者摘要、帳號與權限、顯示偏好、語言、全螢幕及登出 |
| `PortalPageHeader` | 標題、說明、角色／資料範圍、單一主要動作 |
| `PortalFilterBar` | 常用條件、更多條件、查詢、重置、已套用條件數 |
| `PortalSummaryStrip` | 一行 1–4 項摘要；一般列表不可變成大卡片牆 |
| `PortalDataTable` | 載入、空狀態、錯誤重試、分頁、橫向捲動、欄位優先序 |

| `MoneyText` | 原幣、完整金額、方向；禁止用截斷造成金額誤讀 |
| `StatusBadge` | 統一狀態名稱、顏色與說明；不可只靠顏色判斷 |
| `PortalStateView` | 載入、無資料、查詢無結果、失敗、無權限、來源未齊 |

### 1.5 響應式與可用性

- 驗收尺寸至少包含 1440、1280、390、360 px；另做 200% 縮放基本操作檢查。
- 手機側欄採覆蓋式選單；開啟後可捲動並有清楚關閉按鈕。
- 手機查詢單欄排列；表格在自身範圍捲動，不讓整頁水平溢出。
- 金額、幣別、狀態、主要識別及時間不可被裁掉；固定欄不得遮住內容。
- 每個控制有可讀名稱、可見焦點及鍵盤操作；純圖示按鈕必須有標籤或提示。
- 所有畫面使用繁體中文；Demo、正式資料、待核對與缺少來源須清楚區分。
- 頂部列在 390／360 px 不擠壓頁面標題；搜尋、通知與帳號選單仍可操作。

## 2. 代理後台資訊架構

| 分區 | 功能 | 路徑 | 用途 |
| --- | --- | --- | --- |
| 總覽 | 代理總覽 | `/agent/dashboard` | 看營運概況、待辦及資料完整性 |
| 組織管理 | 商戶管理 | `/agent/merchants` | 管理代理樹內商戶草稿及查看商戶狀態 |
| 組織管理 | 下級代理 | `/agent/organization/sub-agents` | 查看與建立下一層代理草稿 |
| 財務中心 | 對帳與佣金 | `/agent/finance/accounting` | 查看平台、下級代理及商戶對帳結果 |
| 報表中心 | 報表查詢 | `/agent/reports` | 單頁呈現商戶、下級代理與注單追蹤 |

舊的 `/agent/reports/merchants`、`/agent/reports/sub-agents`、`/agent/reports/bet-trace` 保留導向單頁對應分頁。第一版不設代理 API／開發者中心；代理的角色是商務推廣與佣金對帳，不自行串接遊戲或管理平台憑證。

## 3. 代理後台頁面規格

### 3.1 代理總覽

查詢：日期範圍、原幣；預設今天與合法預設幣別。Demo 若今天沒有資料，提供「查看示範資料」而不是顯示容易誤解的全零。

| 區塊 | 欄位／內容 | 互動 |
| --- | --- | --- |
| 營運摘要 | 下注筆數、投注人數、投注金額、派彩金額 | 點擊帶入相同日期／幣別前往報表 |
| 組織摘要 | 啟用商戶、啟用下級代理、待完成商戶草稿 | 點擊前往已套用狀態的清單 |
| 待辦 | 待補資料、待核對帳單、即將生效條件 | 只顯示真實可處理項目，最多 5 筆 |
| 資料狀態 | 更新時間、來源完整性、Demo／正式標示 | 缺來源時顯示原因，不用假 0 |

不做：固定趨勢圖、排行榜、RTP、利潤、未核准佣金預估。

### 3.2 商戶管理

常用查詢：商戶代碼／名稱、狀態；更多條件：幣別、Wallet 模式、下級代理歸屬。

| 列表欄位 | 說明 |
| --- | --- |
| 商戶 | 商戶名稱＋代碼 |
| 歸屬 | 直接歸屬代理／代理路徑摘要 |
| 狀態 | 草稿、待審核、啟用、暫停 |
| Wallet | Seamless／Transfer；未知顯示待確認 |
| 幣別線 | 啟用數量＋原幣摘要 |
| 遊戲授權 | 已授權／可用數量，兩者分開 |
| 更新時間 | 最後資料更新時間 |
| 操作 | 查看；符合權限時顯示編輯草稿 |

主要動作是「新增商戶草稿」。草稿只收基本資料、聯絡資料、預計 Wallet 與幣別需求；啟用、正式費率、憑證與遊戲授權仍由有權限流程核准。不得在原型直接顯示建立成功即正式開通。

商戶詳情分頁：概況、幣別與遊戲、商務條件、報表與紀錄。商務條件顯示版本、生效時間與來源；不允許覆寫歷史版本。

### 3.3 下級代理

常用查詢：代理代碼／名稱、狀態；更多條件：層級、直接／全部下級。

| 列表欄位 | 說明 |
| --- | --- |
| 代理 | 名稱＋代碼 |
| 層級與路徑 | L1／L2／L3 與上級摘要 |
| 狀態 | 草稿、啟用、暫停、停用 |
| 商戶數 | 直接商戶／代理樹商戶 |
| 條件狀態 | 已生效版本、待核對或缺少來源 |
| 更新時間 | 最近修改時間 |
| 操作 | 查看；有權限時編輯草稿 |

主要動作為「新增下一層代理草稿」。原型沿用最多三級作示範限制：L1 可建 L2、L2 可建 L3、L3 不顯示新增；此規則需在使用者看過原型後再作最後確認。建立／編輯不包含額度劃轉、充值、人工調帳或即時改佣金。代理代碼、層級與上級建立後唯讀；轉移若未另行確認不提供操作。

### 3.4 對帳與佣金

查詢：期間、原幣／結算幣別、狀態；更多條件：對象代碼、來源完整性。

頁面使用三分頁：平台對帳、下級代理、商戶對帳。

| 列表欄位 | 說明 |
| --- | --- |
| 期間 | 起訖與時區 |
| 對象 | 平台／代理／商戶名稱與代碼 |
| 原幣／結算幣別 | 不固定 USDT；需顯示方向與匯率版本 |
| 來源狀態 | 完整、缺交易、缺條件、缺匯率、待核對 |
| 金額 | 來源未齊時顯示待核對，不顯示正式數字 |
| 狀態 | 草稿、核對中、已確認、有差異 |
| 操作 | 查看詳情 |

詳情包含來源摘要、條件版本、匯率版本、差異及異動紀錄。第一版不提供付款、收款、標記已付、人工調帳或直接修改已確認帳單。

### 3.5 代理報表查詢

單頁三分頁：商戶報表、下級代理報表、注單追蹤。共同保留日期、單一原幣及合法資料範圍；切換分頁保留共同條件。

- 商戶報表：按商戶顯示下注筆數、投注人數、投注金額、派彩金額。
- 下級代理報表：按直接／代理樹下級顯示同四項營運數字。
- 注單追蹤：查詢代理樹內注單；金額原幣呈現，詳情連到來源事件。
- 佣金與財務結果連到對帳頁，不在營運報表重新計算。
- CSV 匯出必須使用目前完整條件並標示資料範圍與幣別。

## 5. 商戶後台頁面規格

### 5.1 商戶總覽

查詢：日期範圍、原幣。

| 區塊 | 欄位／內容 | 互動 |
| --- | --- | --- |
| 營運摘要 | 下注筆數、投注人數、投注金額、派彩金額 | 帶相同條件前往報表 |
| 運作狀態 | 啟用幣別線、可用遊戲、Callback 成功率資料狀態 | 點擊進相關頁，不以假百分比冒充正式監控 |
| 待辦 | 串接缺項、帳單差異、授權變更 | 只顯示自身商戶且可理解的項目 |
| 資料狀態 | 更新時間、來源完整性、Demo／正式標示 | 缺來源顯示原因 |

不做：平台收入、平台成本、平台利潤、代理佣金、排行榜與複雜圖表。

### 5.2 會員查詢

唯讀。常用查詢：會員外部識別、狀態；更多條件：原幣、最後活動時間。

| 列表欄位 | 說明 |
| --- | --- |
| 會員 | 商戶會員識別；不得顯示其他商戶資料 |
| Wallet／原幣 | Wallet 模式與交易原幣 |
| 餘額快照 | 只在有合法來源與更新時間時顯示 |
| 狀態 | 啟用、限制、停用或來源未知 |
| 最近活動 | 最近交易或登入時間，需標來源 |
| 操作 | 查看注單與流水 |

不提供新增會員、批次標籤、風險評分、調整餘額或修改會員資料。

### 5.3 我的遊戲

常用查詢：遊戲名稱／代碼、啟用狀態；更多條件：供應商、類型、原幣線。

| 列表欄位 | 說明 |
| --- | --- |
| 遊戲 | 名稱＋代碼 |
| 供應商 | 供應商名稱 |
| 原幣線 | 已授權且實際可用的幣別線 |
| 類型 | 遊戲類型 |
| 平台狀態 | 上架、維護、停用 |
| 商戶狀態 | 啟用、停用 |
| 更新時間 | 授權或狀態更新時間 |
| 操作 | 查看；平台允許時切換商戶狀態 |

平台停用、維護、未授權或幣別線不可用時，商戶開關停用並顯示原因。批次啟停只有在全部選取項目合法時可執行；否則先列出不可處理項目，不顯示假成功。

### 5.4 注單查詢

常用查詢：注單／局號／商戶原單號、日期；更多條件：會員、供應商、遊戲、狀態、原幣。

列表必要欄位：注單識別、會員、遊戲／供應商、原幣投注、原幣派彩、狀態、下注時間、操作。詳情顯示 Round 關聯、外部識別、交易事件時間線、結果、來源及更新時間；不得把同一 Round 多筆注單合成一筆。

### 5.5 交易流水

常用查詢：交易／注單／商戶原單號、日期；更多條件：會員、事件類型、Wallet、狀態、原幣、異常狀態。

列表必要欄位：交易識別、關聯注單、會員、事件類型、方向、完整原幣金額、狀態、發生時間、操作。詳情顯示來源事件、冪等識別、Callback／Provider 回應摘要及時間線；技術 Payload 預設收合並脫敏。

異常分頁只提供查看與合法查單。通知重送、重新扣款、重派彩及人工補帳未確認前不顯示可用按鈕。

### 5.6 對帳與帳單

頁首使用一行顯示 Wallet 模式、啟用幣別線與未核對項目數，不使用四張大卡。

查詢：期間、原幣／結算幣別、狀態。列表欄位：帳單／對帳識別、期間、原幣、結算幣別、來源完整性、金額或待核對、狀態、更新時間、查看。

詳情包含交易合計、適用條件版本、匯率版本、差異與異動紀錄。商戶只能看自身資料。第一版不提供充值、提款、信用額度申請、標記付款、人工調帳或未核准資金操作。

### 5.7 商戶報表查詢

單頁兩分頁：營運報表、遊戲報表。

- 共同條件：日期、單一原幣；更多條件依分頁提供供應商／遊戲。
- 營運報表：每日下注筆數、投注人數、投注金額、派彩金額。
- 遊戲報表：按遊戲顯示同四項指標；投注人數跨列不可直接相加。
- 點擊資料列可前往已套用相同條件的注單查詢。
- 不顯示平台收入、成本、利潤或代理佣金。

### 5.8 串接設定

單頁四分頁：API 文件、憑證、商戶 API 來源 IP、Callback 紀錄。

| 分頁 | 第一版內容 |
| --- | --- |
| API 文件 | 環境、版本、端點用途、參數、回應、錯誤碼、冪等要求；唯讀 |
| 憑證 | 公開識別、狀態、建立／到期時間；秘密遮罩，更新走受控流程 |
| 商戶 API 來源 IP | IP／網段、環境、狀態、原因、建立與更新時間；只管理商戶 API |
| Callback 紀錄 | 時間、事件、原單號、狀態、HTTP 摘要、查看脫敏詳情 |

第一版不做 OpenAPI JSON 匯入、供應商 Callback 名單、後台登入名單、開發者 API 名單或自由重送 Callback。若已有合法 Sandbox，可提供「驗證連線」；不得建立正式資金事件。

## 6. 共用狀態與錯誤規格

| 狀態 | 呈現 |
| --- | --- |
| 初次載入 | 對應版型骨架，不出現全黑或內容跳動 |
| 無資料 | 說明目前範圍無資料；保留合法主要動作 |
| 查詢無結果 | 顯示已套用條件及重置入口 |
| API 失敗 | 保留輸入、顯示原因與重試；不可拿舊結果冒充新結果 |
| 無權限 | 顯示資料範圍說明；服務端同樣拒絕 |
| 來源未齊 | 顯示缺少哪類來源；財務結果改為待核對 |
| 儲存中／成功／失敗 | 防重送、按鈕狀態明確；成功後更新畫面與操作紀錄 |

## 7. 原型內部製作順序

1. 共用版面、角色切換防護、選單與共用組件。
2. 代理後台五個頁面與舊網址導向。
3. 商戶後台八個頁面與補單入口整併。
4. 桌面／手機、鍵盤、空／載入／錯誤／無權限及跨頁條件回歸。

上述是內部連續製作順序，不設中途使用者等待點。兩套原型與核實報告完成後一次交由使用者檢視。

## 8. 原型核實條件

- 代理與商戶登入後只能到自己的入口與資料範圍。
- 所有側欄項目都有實際頁面；沒有無作用、待開發或回到錯誤入口的選單。
- 代理五頁、商戶八頁的查詢、重置、分頁、詳情、返回與路由條件可實際操作。
- 所有金額完整顯示原幣；沒有固定 USDT、假佣金或假正式帳單。
- 商戶端沒有獨立補單／重送、資金申請與未核准人工操作。
- 一般列表不堆 KPI 卡；列內操作不超載；共用狀態與組件一致。
- 1440、1280、390、360 px 無整頁水平溢出；核心欄位可讀。
- 鍵盤可操作選單、分頁、查詢、表格排序、抽屜與主要動作。
- 頭像選單的帳號與權限、深淺模式、全螢幕、語言及登出均可用鍵盤操作，Escape 關閉後焦點正確返回。
- Demo／正式、待核對、缺來源、錯誤與無權限狀態明確。
- 建置與必要路由／資料範圍檢查通過；不推送、不部署。

## 9. 原型完成後由使用者確認的項目

1. 代理最多三級是否正式保留。
2. 代理是否可建立商戶／下級代理草稿，或只能查看與提交申請。
3. 代理對帳三分頁的正式名稱與財務可見範圍。
4. 商戶是否可自行切換已授權遊戲，及是否需要批次操作。
5. 商戶憑證更新與 API IP 變更是否需要平台審核。
6. 合法 Sandbox 是否保留「驗證連線」，或第一版完全唯讀。
7. 代理／商戶可匯出的報表與敏感欄位範圍。

這些項目可在原型中用安全、可逆的示範互動呈現，但在使用者最終確認前不得視為正式營運規則。

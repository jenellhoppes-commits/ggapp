1. 已接入固定下注時間的商戶逐筆合約引用檢查，對照 merchantId／lineUid／currency，核對對帳筆數，不把演示彙總分攤成明細。下注早於生效日即沿用舊版，與晚結算無關。原型注單明確標記演示來源 Asia/Taipei 時間，正式來源必須提供含時區時間。

## 2026-09-08 結算引用前置更新

- 新增 `settlement-contracts.ts`：依日期列出合約覆蓋分段，逐筆引用可明確指定下注或結算完成時間，按平台時區選版；保存合約識別、版本、日期、費率／基礎／幣別／帳期副本。
- 使用者已確認以「下注時間」選用新舊費率，平台時區生效日 00:00 起下注採新費率。商戶逐筆流程固定使用 betAt，不允許切換成結算完成時間。
- 缺生效合約、缺逐筆明細、時間缺時區、重複識別、超出期間一律拒絕，禁止拿目前費率補算歷史。
- 對帳詳細的「計算快照」新增期間合約覆蓋檢查，清楚區分現在查到的合約與歷史快照。舊演示快照缺版本時顯示缺失，不回填成假追溯。
- 原型重算方法改為拒絕，不再僅更新時間卻回報成功；尚未實作正式金额分段計算、跨期退款、捨入及付款。原有彙總演示無逐筆對帳資料鏈，不能均分或按天攤分推造金額。
- 測試涵蓋午夜時區邊界、分段、引用副本不隨合約改動、缺資料及重複交易，以及檢查不修改舊對帳或操作紀錄。未部署。

## 最新權限更正

使用者更正：代理可查看下級代理內容，並修改授權範圍內下級代理及商戶的費率；帳務層面可有操作，但不能修改其他設定或強制改寫對帳單。取代原先「不含下級、代理全部唯讀」的規定。商戶自己的操作權限沒有因此擴大。

已確認的帳務寫入為直屬費率調整，免審核、不得高於上級、每次必填生效日期。帳期、結算幣別、調帳申請、確認對帳與付款等其他操作仍須逐項定義，不能從「帳務層面可以」推定全部開放。費率變更不能作為繞過限制、強制重算或覆蓋既有對帳單的途徑。

### 本版不納入

- 代理非帳務設定修改、商戶新增／正式啟用、調整錢包餘額、補單／重新派彩、強制改寫對帳單、付款執行或敏感資料匯出；費率調整已納入規格，完整合約其他欄位權限另定。

商戶試玩連結目前已有建立、停用及重新產生等演示操作，與新確認的唯讀首版不同。本文件將其列為「既有演示、首版例外尚待處理」，不視為已批准的唯讀例外，也不在本次整理中刪除功能。兩端發布前須決定保留為明確演示例外、限制為查看，或另列後續範圍；代理不因此獲得試玩操作權。

### 現況缺口

1. 登入為前端演示；商戶示範身分固定綁定 `M00001`，代理示範身分目前沒有 `agentId`。正式開發前須建立可靠的身分與組織歸屬。
2. 角色選單／路由限制不是資料安全邊界；localStorage 與前端可取得的共享資料不具正式租戶隔離。
3. 示範登入回傳通用操作標記，不能據此判定代理／商戶具有新增、修改、匯出、審核權限。
4. 既有管理者報表 `useReportFourTabs` 僅允許 `R_SUPER`／`R_ADMIN`，使用管理者演示資料範圍，不能直接把頁面複製給代理／商戶。
5. 全部下級代理及其商戶已納入可見範圍；缺歸屬期間資料，不能以目前 agentId 直接核准轉移前全部歷史交易資料。

### A-01 總覽與摘要

- 目前「12 家商戶」「4 家串接中」「284,500 USD 已確認佣金」等均為固定示意，尚未以代理身分查詢。開發時改成資料來源驅動，未接資料顯示「尚未提供」，不能沿用示意數字假裝正式統計。
- 建議查詢條件：日期區間、幣別、商戶；預設商戶範圍由身分授權決定，不能讓網址參數擴大範圍。
- 多商戶投注人數須先決定識別與去重口徑；不得把各商戶人數直接相加後標為跨商戶不重複人數。
- 營運摘要與佣金分開：投注結果不是已確認佣金，也不是已付款金額。

### A-02 佣金與付款

- 既有路由描述以已確認商戶結算作為正式佣金依據；此為入口規劃，實際公式、層級分配及成立時點尚未核准。
- 建議資料分開保存佣金計算結果與付款紀錄，畫面不得把「確認佣金」等同「完成付款」。部分付款、多筆付款、撤銷／更正政策需確認。
- 代理可調整下級及商戶費率；佣金與付款頁目前仍規劃為查詢，帳務申請、審核、付款與收款帳戶維護須逐項確認，不直接擴大權限。
- 管理者原有代理條件、對帳頁與示範估算不等同代理端已具備此功能；不得照搬百分比差額公式。

### M-01 幣別線與正式串接

- 延續商戶→幣別線→授權遊戲關係，同幣別可用不代表已取得該遊戲授權。
- 目前 Wallet 模式由商戶層級設定並帶入幣別線；不可未經確認改為各線獨立切換。
- 建議明確分開測試與正式環境、憑證與結果。首版不開放修改回呼、白名單、輪替憑證及正式啟用；可見欄位與遮罩仍需逐欄核准，後續可寫流程另訂。
- 真正 API 測試須保留請求識別、環境、測試案例、時間、結果、錯誤碼及去敏感 Trace。畫面按下「測試」不等於正式驗收通過。
- 原有管理者商戶詳情的串接測試演示，不代表 `/merchant/integration` 已完成。

### M-02 試玩連結：目前已實作的演示規則

- 使用與管理者試玩管理相同的 `DemoLinks` 元件與 store，不複製另一份連結資料。
- 商戶僅能看到用途為商戶試玩且 merchantId 等於自身的連結；建立及修改也檢查這個邊界，代理不因此獲得試玩權限。
- 一個連結綁定一供應商、一遊戲、一幣別線、語系、到期時間；可選成功啟動次數上限，初始額度僅在能力允許時提供。
- 檢查商戶啟用、同幣別測試線路、明確遊戲授權、Wallet 相容、供應商／遊戲可用、語系及試玩免計費能力；任一不符即拒絕。
- 狀態包含有效、停用、到期、次數用盡、不可用及已替換；重新產生建立新連結並保留舊歷史，舊連結失效。停用只禁止新啟動，不代表能終止既有連線。
- 模擬失敗不增加成功次數；試玩連線與事件排除正式錢包、注單、供應商應付、商戶結算、代理佣金及平台毛利。
- 連結只存在目前瀏覽器的本地演示資料，不能承諾跨裝置分享、真實遊戲啟動、原子次數上限或正式憑證安全。

### M-03 交易查詢

- 建議分開注單與事件流水：每次投注有可追溯注單，退款／回滾／重送事件以關聯 ID 連回來源，不以覆蓋舊紀錄代替事件歷史。
- Seamless／Transfer 模式能提供的交易類型需依實際能力決定，不能在所有商戶都開放轉入／轉出。
- 金額保留原幣、符號、精度；畫面展示規則需與總後台共用，跨幣別不直接加總。
- 查詢重複事件、逾時、失敗與尚待處理時，不應給商戶未經授權的補單、改帳或重新派彩操作。

### M-04 結算與帳單

- 原交易結果、商務費率、換算匯率、最終結算與實際付款應可區分並追溯；匯率鎖定後不得隨最新匯率刷新而改變歷史確認結果。
- 建議顯示商戶自身適用合約條件與版本，但不公開供應商採購費率或代理分配內部條件。
- 本次已確認的「修改費率必填生效日、未修改持續沿用」是供應商合約原型要求。是否完整套用代理／商戶條件，須另行確認，不能宣稱這兩端已實作。
- 費率修改、跨期調整、負 GGR、退款跨期、匯率來源、精度與捨入、日／週／半月／月帳期，以及帳單到期規則均待財務規格核准。

## 5. 共用畫面規格建議

1. 沿用總後台共用頁首、篩選、表格、空資料與錯誤呈現；共用不等於共用全部資料／權限。
2. 適用的查詢頁提供本日、昨日、本週、上週、本月、上月；先選取草稿，按查詢套用，查詢與分頁可由 URL 還原。
3. 日期快捷沿用週一起算、本週／本月截止今天的元件；兩端報表統一採平台時區且明示。查詢資料的時間欄位、區間邊界及帳期截止仍須於各模組定義，不得把時區已確認等同所有時間口徑已完成。
4. 幣別字典、啟用狀態、顯示精度、語系與主題讀取全域設定；可選幣別再交集自身授權範圍，不寫死 USD／TWD。
5. 手機篩選欄位上下排列、表格可捲動，日期面板不超出視窗；點擊不誤縮放，鍵盤焦點可操作。既有共用手機修正在本地尚未部署，不代表兩端實機驗收完成。
6. 查詢需區分載入中、無資料、未設定、無權限、來源錯誤。尚無正式帳務時不以 0、示意數字或假成功代替。
7. 首版不開放匯出。未來若開放，須另核准獨立權限、欄位、租戶、數量範圍與下載稽核，並沿用共用 CSV 安全處理。

## 8. 建議開發順序與驗收

### 第一階段：角色與唯讀資料主幹

- 補代理／商戶身分綁定及 API 層資料隔離，建立 A 代理／B 代理、A 商戶／B 商戶測試組。
- 代理：推廣商戶、串接進度；商戶：幣別線、串接狀態、可用遊戲。
- 總覽改為真實同範圍查詢或明確未接資料狀態，不顯示固定示意財務數字。
- 驗收代理 A 只能看授權下級與商戶，不能查看其他代理體系；商戶 A 不能直連商戶 B 的詳情。未綁定身分與來源錯誤必須拒絕或明示，不回退為全平台。

### 第二階段：營運查詢

- 商戶會員、注單、交易流水；代理營運摘要。
- 驗收查詢／清除／排序／分頁／URL 還原、日期快捷、幣別與時區一致，以及手機操作。
- 抽查任何列表項目進入詳情後仍屬登入範圍；自行修改 URL、識別碼或匯出參數不得越權。
- 費率修改依獨立對象授權；其他未核准寫入與匯出不開放，不只隱藏按鈕，也要禁止直接呼叫。驗收相同條件下總覽、清單、分頁與詳情口徑一致，平台時區跨日不錯位。

### 第三階段：核准後的帳務

- P04–P07 決策完成後，才實作商戶結算／帳單、代理佣金／付款紀錄與必要覆核。
- 驗收合約版本適用、跨期規則、匯率鎖定、既有歷史不被新條件修改，以及未付款不顯示已付款。
- 試玩資料不得流入任一正式營運／結算統計；取消授權、過期或停用後，重新檢查可用能力。

上述為建議順序，不是已承諾的排期或全量開發授權。

### 開發前需完成的資料契約

身分綁定、商戶／線路統一識別、白名單欄位、歸屬歷史策略與指標定義須先收斂；G01–G08 的完整對照見欄位檢核文件。三項範圍確認不代表這些技術與商務缺口已修復。

# GGAP MVP 已確認規格覆蓋決議

版本：GGAP-MVP-DECISIONS v1.0｜日期：2026-09-05｜狀態：使用者已確認

本文件覆蓋先前仍標示「待確認」的同類內容。未列出的財務公式、權限與正式資料來源仍維持原本待核對狀態，不可由原型自行推定。

## 1. 已確認的功能範圍

1. 財務中心側欄只保留「供應商對帳、代理對帳、商戶對帳」三個入口；差異處理與異動紀錄整合進對帳工作頁或詳情，不再各自占用側欄。
2. 匯率是必要財務能力，但整合進財務設定或相關對帳流程；不得固定 USDT 為唯一基準幣。匯率來源、方向、有效時間與版本必須可追溯。
3. 維護設定第一版只保留立即開啟／解除維護，不提供排程維護。
4. 網路名單第一版只管理商戶 API 來源 IP；後台登入、供應商 Callback、開發者 API 等範圍暫不納入。
5. 開發者中心第一版只保留唯讀文件、端點、參數、回應、錯誤碼與必要測試資訊；移除 OpenAPI JSON 匯入。

## 2. UI／UX 與共用組件要求

- 一般管理頁不堆疊四張 KPI 卡；統計卡集中於儀錶板與報表。必要摘要使用一行緊湊呈現。
- 每頁只保留一個主要動作；資料列保留「查看」或最高頻操作，其餘放入有文字標籤的更多選單。
- 查詢區統一為 2–4 個常用條件、「更多條件」、查詢、重置；收合後仍要顯示已套用條件。
- 共用表格、分頁、抽屜、表單、空狀態、載入狀態、錯誤狀態、無權限狀態與確認提示必須採一致組件與互動。
- 金額、幣別、狀態、主要識別與時間不可被截斷或誤讀；次要欄位移到詳情。表格需要明確水平捲動與合理固定欄位。
- 桌面 1280／1440 與手機 390／360 寬度皆須可操作；手機主內容不得水平溢出，表格可在自身區域捲動。
- 互動控制須有可讀名稱、鍵盤焦點、選取與停用狀態；純圖示按鈕必須有名稱或提示。
- 頂部歷史頁籤限制可見數量，提供清楚溢出與關閉；手機簡化或隱藏，不得占用主要閱讀高度。
- 列表返回保留查詢、頁碼與捲動位置；跨頁跳轉承接合法的日期、幣別與對象條件。
- 繁體中文文案與語系鍵需完整；演示資料、正式資料、待核對與缺來源狀態不得混淆。

## 3. 驗收最低條件

每一批交付至少核實：主要任務可完成、查詢與重置、表格必要欄位、空／載入／錯誤／無權限、桌面與手機、鍵盤與可讀名稱、跨頁條件承接，以及共用組件在各頁的一致性。規格核實通過後才交付獨立驗收；缺陷修復後回到相同範圍複驗。

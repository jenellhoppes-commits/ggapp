# 供應商成本與結算：人工維護要求

2026-09-07 使用者補充：成本與結算需手動加入，開發人員不會知道詳細數字。

## 已確認要求

- 真實商務數字由管理端手動維護，不要求使用者提供給開發人員，不寫入程式碼、測試資料或版本庫。
- 開發只需欄位定義、驗證規則及虛構測試資料，不需要真實合約數值。
- 人工維護的是合約費率與結算條件，不是每期結算金額；金額由適用條件與交易資料計算。

## 已確認的生效與版本規則

- 首次填寫合約費率、結算條件與生效日期，建立首個版本。
- 未修改時持續沿用原版本，不需每期重新填寫，不自動到期或歸零。
- 日後修改費率或結算條件，沿用相同填寫流程，必須指定新版本生效日期。
- 生效日前沿用舊版本，生效日起適用新版本；不是結帳時一律套用最新費率。
- 下次結算按該期間適用的版本計算；若跨越版本生效日，按生效日前後分段採用條件。
- 保留歷史版本，已完成結算不因條件修改而改寫。

### 驗收情境

- 未修改條件：跨多個帳期仍沿用同一費率。
- 新版尚未生效：生效日前仍採舊費率。
- 帳期內有新版生效：前後期間分別採用相應版本，不將全期套用新費率。
- 新增或修改版本：缺少生效日期不能儲存；已完成結算保持不變。

## 原型實作更新（2026-09-07）

- 「成本與結算」已接入 ProviderTerms 原型：新增／修改條件、必填生效日、版本紀錄、目前生效／下一版本狀態及未儲存離開確認。
- 表單包含計費基礎、費率／每期固定費用、結算幣別、週期、生效日期、備註。GGR／有效投注百分比及固定費用為原型選項，不代表正式計算規則已核准；未填費率保持空值，明確輸入 0 才代表零費率。
- 結算幣別讀取全域已啟用結算幣別；日期顯示依平台時區，每份版本記錄時區、建立人及時間。
- 修改帶入最新版本內容，生效日期留空要求重填；儲存只追加版本，同時新增不含費率數字的操作紀錄。沿用供應商管理角色權限，儲存時檢查版本衝突。
- 原型暫不開放追溯日期、同日覆蓋或改寫已排定版本：生效日不得早於本日，且必須晚於上一版本。此為保守原型限制，正式追溯／覆核流程仍待確認。
- 保留既有正式結算阻擋；未連接帳務計算，不產生應付、不重算歷史、不寫入真實合約數字。正式分段結算與捨入仍未實作。
- 驗證：型別檢查、建置、修改檔案 ESLint 通過；版本單元測試涵蓋空值、日期、零費率、權限、衝突、舊版保留與持續生效；既有供應商／對帳檢查通過。
- Chrome 瀏覽器流程通過：空狀態、驗證、新增、修改必填新日期、兩版並存、生效／待生效、重整保存、手機顯示、取消保護。證據位於 `docs/qa/provider-terms/`，全部使用隔離瀏覽器中的虛構數值，不會預填到使用者瀏覽器。

## 仍存在的正式環境限制

- 現有 providerDemo store 使用瀏覽器 localStorage，只適合隔離演示，不是正式機密合約資料庫，不应在此輸入真實成本。
- 正式供應商計費基礎、負 GGR 與捨入規則尚待決策；不得沿用舊公式假裝完成。

## 後續實作建議（尚未實作）

- 提供有權限人員的新增／編輯表單；未設定與數值 0 分開，未完整設定時禁止正式計費。
- 合約條件按供應商、適用範圍及生效期間保存版本，已確認的歷史帳務不可被新條件回寫。
- 候選欄位：計費基礎、費率或固定費用、結算幣別、帳期、生效日期、備註。實際欄位依合約類型確認，不預填假定條件。
- 正式環境需後端權限、保護儲存、異動紀錄及必要覆核；前端隱藏欄位無法保證開發者無法存取正式資料。
- 計費基礎、負 GGR、捨入、生效日期的時區／邊界及追溯修改規則仍需另行確認；上述生效版本規則不代表已決定全部計算細節。

# GGAP 單頁四報表：正式開發規格

版本：R03-REPORTS-4TABS v1.0

狀態：使用者已確認並要求優先開發完成；實作與驗收狀態由安排選手另行追蹤。

範圍：管理者原型。此版優先於既有分散式報表方案；保留商務管理、內容管理、交易中心、財務中心、系統管理五大區塊。

## 1. 授權、優先級與交付界線

使用者確認：「好的，整理出詳細的開發規格後提交給安排，讓安排這邊讓開發優先依照這一版開發完畢。」

本文件將 GGAP_REPORTS_FOUR_TABS_DRAFT.md 的已確認方案轉為執行規格。安排選手須將本版設為當前優先交付，取代舊R03分散到各頁的完整報表實作；不要同時開發兩套報表。必要的五區塊導航與注單查詢連接列為本版依賴，不須等待其他完整模組全部完成。

先交可操作本機畫面並持續做到本版範圍完成，不因交付預覽而停下等待例行批准。各角色進度及阻擋只回安排選手，規劃選手不接收自動回報。此次沒有對外推送或部署批准。

## 2. 導航與畫面

- 唯一側欄入口：「商務管理 → 報表查詢」。商務管理順序為商戶管理、代理管理、報表查詢。
- 頂層維持五區塊，不新增頂層報表中心或總覽。
- 同一頁四分頁，名稱及順序固定：「運營報表、代理報表、商戶報表、遊戲報表」。首次進入選運營報表；有效網址指定則還原指定分頁。
- 畫面自上而下：頁面名稱、四分頁、查詢列、四項統計、一張表格及分頁。
- 四項統計順序：「下注筆數、投注人數、投注金額、派彩金額」，均為完整已套用查詢結果，非目前頁。
- 表格不再放重複合計列。僅顯示選中分頁的一張表，切換時不堆疊其他表格。
- 沿用目前深色版型與元件，不更換框架。手機分頁可橫向捲動，表格水平捲動限制在表格區域。
- 第一版不新增圖表、排行榜、同期比較、占比、GGR、有效投注、淨收益、RTP、ROI、成本、毛利、佣金估算或自訂報表。

## 3. 四分頁欄位

每張表最後一欄為「查看注單」。日期、代碼、名稱不可被截斷至無法識別，長識別可查看完整內容。

| 分頁 | 每列維度 | 專屬查詢 | 表格欄位 |
| --- | --- | --- | --- |
| 運營報表 | 平台時區的一個日期 | 無 | 日期、下注筆數、投注人數、投注金額、派彩金額、操作 |
| 代理報表 | 下注當時直接歸屬代理；另保留未歸屬/歸屬待確認群組 | 代理選擇，預設全部授權範圍 | 代理代碼／名稱、下注筆數、投注人數、投注金額、派彩金額、操作 |
| 商戶報表 | 一個商戶 | 商戶選擇，預設全部授權範圍 | 商戶代碼／名稱、下注筆數、投注人數、投注金額、派彩金額、操作 |
| 遊戲報表 | 供應商與平台遊戲識別組合 | 供應商、遊戲名稱／代碼 | 遊戲代碼／名稱、供應商、下注筆數、投注人數、投注金額、派彩金額、操作 |

名稱相同的商戶、代理、遊戲不能合併為同一列。代理報表是管理者的統計維度，不授予代理登入帳號新增會員/逐筆下注權限。

## 4. 查詢狀態與操作

### 4.1 共用條件

- 日期範圍必填，預設平台時區今日；起訖皆為使用者所見日期，資料查詢轉為起日00:00包含、迄日次日00:00不包含。不可使用瀏覽器時區靜默取代平台時區。
- 原幣別必填且單選。沿用使用者上次合法選擇，首次未選則提示選擇，不硬編預設TWD/USDT；沒有合法幣別時呈現缺設定。
- 日期倒置、缺必填、無效日期/幣別時不送查詢，保留輸入並在欄位顯示原因。
- 正式資料只使用正式環境，Demo/Sandbox排除。演示模式使用隔離且一致的模擬来源，明示演示，不把試玩啟動當正式下注。
- 平台時區、所選幣別及資料更新時間在頁面可辨識，不新增一整列技術資訊。

### 4.2 提交、切換與還原

- 編輯中的條件與已套用條件分離；按查詢或Enter才更新列表及統計，查詢回第1頁。
- 切換分頁保留已套用的日期/幣別，清除專屬条件及未提交輸入，回第1頁；以保留的已套用條件載入新分頁。沒有合法共用條件則提示選擇，不自動查全部幣別。
- 重置將日期回今日，保留目前合法幣別，清除專屬條件與排序，回第1頁並重新查詢；無合法幣別則等待選擇。
- 每頁10/20/50筆，預設20筆；切換筆數回第1頁，保持查詢與排序。
- 運營預設日期由新到舊；其他分頁預設投注金額由大到小，使用穩定唯一識別作同值排序次序。使用者可對四項數字及運營日期排序。
- 已套用的分頁、日期、幣別、專屬篩選、排序、頁碼/筆數可透過非敏感網址條件還原。無效分頁回運營，無效排序/頁碼/筆數回合法預設；非法日期/幣別提示修正，不擴大資料範圍。
- 非同步快速切換或查詢時，舊回應不得覆蓋較新條件。列表、統計、更新時間使用同一份結果。
- 頁碼超過結果最後一頁時回合法頁並顯示正確資料，不顯示假空結果。

## 5. 已確認的營運統計口徑

這四個指標是原始營運觀察值，不是有效投注、退款後淨額、正式結算或佣金基礎。

| 指標 | 定義 |
| --- | --- |
| 下注筆數 | 已成功受理、原始下注時間在查詢範圍的原始下注唯一識別數。之後退款/取消保留原成功下注事實，不按目前最終狀態把它當從未下注 |
| 投注人數 | 上述下注來源中，以環境＋商戶＋會員識別去重。統計區重新對完整範圍去重，不加總各列人數 |
| 投注金額 | 上述去重下注原幣金額加總，不包含失敗請求、轉點或重送，退款/取消不隱含扣除 |
| 派彩金額 | 與上述下注範圍明確關聯、截至資料更新時間已成功的原幣派彩事件去重加總；退款、取消、回滾事件不混為派彩或隱含抵銷 |

下注按原始下注時間歸入平台時區日期；關聯派彩回歸該下注範圍。遲到派彩會更新歷史營運報表，畫面與匯出標示資料更新時間，不更動鎖定的財務快照。

### 5.1 關聯與資料缺口

- 同局多筆下注仍分別計數。派彩按來源事件唯一鍵去重，不能把局級派彩複製到每筆下注。
- 局級派彩只有在日期、代理、商戶、遊戲分組及查詢邊界的歸屬明確時才可計入相應分組一次。跨分組或無法確認時，受影響派彩欄和統計派彩顯示「資料待確認」，不平均分攤，不以可識別部分小計冒充完整金額。
- 已確認沒有派彩事件且來源完整可顯示0；缺來源、未載入或關聯不完整不是0。
- 代理採下注當時有效的商戶直接代理關係；不向上重複累加。明確無代理列「未歸屬」，缺歷史依據列「歸屬待確認」。篩選全部時保留兩群組，不能丟棄資料來湊對帳。
- 帳號/名稱更新不改歷史識別，現今代理關係不回填舊下注。
- 金額採既有精確十進位處理與幣別精度，不用格式化字串計算或混幣相加。
- 若現有資料無法判定曾成功下注、派彩去重或當時代理，明示缺來源並回安排追蹤；原型可用一致的明示模擬來源展示，不虛構正式映射或默稱實際資料完成。

## 6. 資料輸入與結果契約

以下是共用查詢層需要表達的內容，不要求建立新API或更換既有資料模型。可沿用已存在等義欄位，但四分頁必須共用來源及聚合規則。

| 區域 | 必要內容 |
| --- | --- |
| 查詢 | 報表類型、日期起訖、平台時區、原幣別、適用代理/商戶/供應商/遊戲條件、排序、頁码/筆數 |
| 強制範圍 | 目前登入者及伺服器授權範圍、正式/隔離演示環境；不得相信網址自行指定權限 |
| 原始下注 | 唯一來源/下注識別、曾成功受理的依據、原始下注時間、環境、商戶、會員、供應商/遊戲、原幣金額、當時代理歸屬或明確未知 |
| 派彩事件 | 唯一來源事件識別、成功依據、原幣金額、關聯下注或局識別、可判定歸屬的來源 |
| 查詢結果 | 已套用條件、完整查詢四項統計、分組總列數、當頁列、更新時間/結果版本、資料完整性狀態 |
| 每列 | 穩定分組識別、展示名稱/代碼、四指標及其完整性、適用注單明細範圍 |

結果中的金額以既有精確金額表示傳遞，不以10K等文字當原值。缺失值與真正0分開；完整性提示只有影響使用者判断時顯示。

## 7. CSV匯出

- 第一版只提供所選報表CSV，不做四報表打包、定時寄送、PDF或自訂欄位工具。
- 匯出已套用查詢的全部分組列及排序，忽略分頁限制；編輯中未提交條件不能影響匯出。
- 使用與畫面同一次查詢的來源版本/截止時間。若無法保留該版本，先重新載入畫面與匯出，不靜默匯出另一組數字。
- 欄位包含報表維度、四指標、原幣別、查詢起訖日期、時區、資料更新時間。無操作欄；缺值列出資料待確認，不空轉為0。
- UTF-8可正確開啟繁體中文；逗號/引號/換行正確逸出，文字儲存格避免試算表公式執行，真實負數金額仍依數值輸出。
- 檔名包含報表類型、期間、幣別。無權限不顯示可用匯出操作，產生及下載亦檢查範圍；正式後端未驗證須如實交付。

## 8. 明細連接與舊網址

- 運營列帶入該日；代理/商戶/遊戲列帶入該分組識別，並保留日期、原幣別、環境及授權範圍。
- 注單管理須能承接同一來源/歷史代理歸屬語意，不能用現今商戶代理篩選代替。明細不因查看按鈕而移除原有權限。
- 從商戶/代理詳情看報表時，帶入相應分頁和對象；缺少日期/幣別按本版規則處理。
- 報表不提供修改注單、人工送單、補款或重送交易。
- 舊運營/代理/商戶/遊戲報表網址指向同一報表頁對應分頁，保留適用查詢條件。
- 舊會員/交易報表導向會員或注單/交易頁；舊結算報表導向對應財務頁，無足夠主體資訊時要求選擇，不任意挑商戶結算。
- 獎池、活動、RTP、品質與補單送單等已移除功能顯示停用說明，不轉到無關報表。
- 實際canonical路徑由開發沿用已存在可相容路徑，交付時須列唯一正式入口與所有舊路由對照，不要求無意義的全站路由改名。

## 9. 空資料與異常

- 尚未選幣別：提示選擇，不顯示假統計。
- 載入中：保持布局及明確載入狀態，避免短暫0值冒充查詢結果。
- 完整查詢無下注：統計0、表格無資料，保留查詢。
- 查詢失敗：顯示錯誤與重試，不拿舊結果冒充新條件。
- 個別來源缺口：可保留有依據的指標，受影響值顯示資料待確認；匯出一致。
- 權限不足：拒絕查看/下載，不因切分頁、改URL或關聯跳轉擴張範圍。

## 11. 可重跑的驗收案例

所有案例使用隔離資料與固定截止時間，不直接修改使用者共用業務資料。

| 編號 | 檢查 | 通過條件 |
| --- | --- | --- |
| R4T-01 | 導航與內容 | 五大區塊、商務管理內唯一報表入口、四分頁名稱順序正確，每次只有四數字與一張表 |
| R4T-02 | 四分頁來源核對 | 相同條件下，完整來源的下注筆數/投注金額/派彩金額可核對，投注人數按範圍去重 |
| R4T-03 | 去重及事件排除 | 重送下注/派彩不重算，轉點/失敗下注/Sandbox不混入，退款不被當派彩 |
| R4T-04 | 會員識別 | 同商戶同會員跨遊戲只算一人，不同商戶同會員字串不誤合併 |
| R4T-05 | 歷史代理 | 改現今代理不改舊下注歸屬；未歸屬及缺歷史群組不丟失 |
| R4T-06 | 時間邊界與遲到派彩 | 按平台時區起含迄不含，遲到派彩歸原下注查詢；固定版本的畫面/匯出一致 |
| R4T-07 | 局級派彩 | 同一分組內只算一次；跨分組/查詢邊界不明時顯示待確認，不分攤或重算 |
| R4T-08 | 查詢狀態 | 未提交不改結果，Enter/查詢、重置、分頁切換、URL還原及無效條件正確 |
| R4T-09 | 分頁排序及舊回應 | 超過50列10/20/50無重漏，按原值穩定排序，過期回應不覆蓋新條件 |
| R4T-10 | CSV | 匯出全部查詢列，與畫面同版本/口徑，中文/特殊字元正確，未知不變0 |
| R4T-11 | 注單與舊網址 | 四種明細帶入精確條件，舊報表分頁對照正確，退役入口不錯導 |
| R4T-12 | 權限及狀態 | 切分頁/改URL/匯出不擴權，缺資料/無資料/載入/失敗正確區分 |
| R4T-13 | 畫面可用性 | 桌面及390px可操作，既有共用360/768/1280/1440/1920與200%檢查按實際執行記錄，未測不算通過 |

最低數值對照樣本：同一正式原幣/同日/授權範圍內，B1=M1/U1/G1下注100派彩150；B2=M1/U1/G2下注50且完整來源無派彩；B3=M2/U1/G1下注200派彩100；B4=M1/U2/G1下注80之後退款80。全部曾成功下注，B1重送一次且其派彩亦重送一次，另有轉點1000與Sandbox下注。整體應為4筆、3人、投注430、派彩250。M1為3筆/2人/230/150，M2為1筆/1人/200/100；G1為3筆/3人/380/250，G2為1筆/1人/50/0。遊戲列投注人數相加為4但整體仍為3，不能直接求和。金額只為隔離驗收樣本，不是產品預設值或正式結算例子。

## 12. 開發與交接順序

1. 核對現有未提交修改及R03/R04依賴，保存使用者修改；建立本版單一來源、已完成/待完成對照。
2. 完成五区塊必要導航與單頁四分頁畫面，沿用元件。
3. 完成共用聚合、查詢、分頁、統計與缺來源狀態，接一致原型資料。
4. 接明細、CSV及舊路由相容，移除重複報表入口與重複完整報表區塊。
5. 基本自測後即提供預覽，繼續完成本版剩餘項目；獨立驗收鎖定具體版本，有缺失修復複驗，確認原型與本文件一致。

交付包必須列本版編號、實际來源目錄、完整修改檔案及基線/版本、預覽入口、R4T驗收結果、已完成/未完成/缺來源/未驗證項與畫面證據。不把只有側欄或占位表格稱為本版完成。必要能力缺來源不能直接省略驗收或強稱全數完成，由安排追蹤並向使用者說明。

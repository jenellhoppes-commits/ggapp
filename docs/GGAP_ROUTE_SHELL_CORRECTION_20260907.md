# GGAP 路由與新版殼層修正

日期：2026-09-07｜狀態：使用者已直接指定

## 修正原因

目前由乾淨基準啟動的畫面使用 History 路由，例如 `/admin/transactions/ledger`，且仍呈現舊版淺色殼層。使用者已指出這不是要核對的新原型，並指定操作紀錄入口為：

`http://127.0.0.1:3016/#/platform/access/logs`

舊畫面證據：`docs/references/old-shell-wrong-entry-20260907.png`。此圖只用於標示錯誤基準，不得作為目標設計。

## 已確認修正

1. GGAP 新原型改用 Hash 路由，可直接解析 `/#/platform/access/logs`。
2. `/platform/access/logs` 是「人員與權限」中的「操作紀錄」頁，不是獨立舊系統管理頁。
3. 原 `/admin/system/audit-logs` 保留相容導向至 `/#/platform/access/logs`，不得出現兩套不同操作紀錄。
4. 儀錶板、管理者、代理與商戶入口均使用同一個新殼層與共用組件，不再以舊版淺色 Master／Merchant Layout 作為可交付畫面。
5. 新殼層需套用已核准的分區平列側欄、頂部頁籤／導覽及共用帳號選單；代理與商戶仍依各自角色與資料範圍顯示選單。
6. 本地交付前需以實際瀏覽器直接輸入上述網址驗證刷新、返回、前進、登入導向與頁面內容。

## 驗收條件

- 直接開啟 `http://127.0.0.1:3016/#/platform/access/logs` 可到操作紀錄。
- 畫面顯示在「人員與權限」脈絡內，包含帳號、角色、操作紀錄三個同主題入口或分頁。
- 不再顯示使用者截圖中的舊版 GGAP 淺色殼層。
- 代理／商戶原型使用新殼層，且不能看管理者操作紀錄或跨角色資料。
- 不讀取或複製 `game-admin`；只依本文件、既有核准規格與使用者提供的視覺參考在 GGAP-Workspace 實作。

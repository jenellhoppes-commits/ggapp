## 3. 資料契約與相容方式

### 3.1 一般能力與試玩能力分開

一般線路：設定及示範憑證、模擬檢核通過、已知 Mock 幣別／精度／錢包、同幣別遊戲來源、Sandbox。種子 Adapter 只認 TWD／USD、Seamless、2 位小數、最小單位 0.01；這不是正式供應商能力認證。

遊戲可用性：再檢查供應商／線路啟用、遊戲平台上架、來源可用、遊戲支援該幣別。

綁定商戶：再檢查商戶狀態、同幣別線路、線路與 Sandbox 狀態、商戶遊戲及線路遊戲都明確授權、商戶層級 Wallet 相容。Testing 只表示可進行本地測試，不表示已正式啟用。

試玩：再檢查原生 Demo／核准 Sandbox、排除供應商計費、遊戲試玩支援、語系及初始額度能力。未綁商戶的內部試玩不查商戶授權；任何綁定商戶的試玩都檢查交集。

正式線路仍不能在演示中啟用或啟動。不新增逐線切換商戶 Wallet；所有線路繼承商戶層級設定。

### 3.2 本地資料保留

- 沿用 `ggap-provider-demo-v1`，沒有清除 links、sessions、audit、provider ID、game ID 或 line ID。
- 既有供應商只追加已知種子 `integration` 能力；新建但沒有 Mock 契約的供應商不會自動獲得能力。
- 遊戲只補 `version`、`sourceName`、`sourceAvailable`、`type`，同步後追加 `syncedAt`。舊的人工 `name`、標籤及平台上架狀態保留。
- 商戶資料直接使用既有 BusinessPartner Store。新增三個本地演示鍵：`ggap-business-merchants-v1`、`ggap-business-games-v1`、`ggap-business-line-games-v1`。首次沒有鍵時使用現有種子；已有鍵不重建。這些是既有演示商戶資料，不能輸入真實憑證。
- Provider Store 的商戶投影只含身分識別、狀態、錢包模式、線路／環境可用性及遊戲 ID；不複製商戶或供應商密鑰。
- 同頁授權異動即時重新投影；新分頁從同一組演示鍵讀取。這不提供伺服器授權、防竄改或跨分頁交易原子性。
- 既有登入快取若缺少新 `merchantId`，商戶試玩會保守拒絕操作；重新登入本地商戶帳號可取得範圍，不以 userId 猜測。

### 3.3 連結替換與同步保護

- 重新產生新增 id/token，舊紀錄加上 `replacedById` 並停用，新紀錄記 `replacesId`；舊 token、期限、starts、createdAt 與 Session.linkId 不改。
- 已替換的舊連結不再分岔產生新版本，請從最新版本操作。舊網址可顯示已替換狀態，但不能建立新 Session。
- 本批以前已被舊程式覆寫掉的 token／期限沒有可靠來源可重建，不假造歷史。
- 同步以供應商 ID + 來源遊戲代碼比對，重跑只更新來源欄位，不改人工名稱、授權及平台上架。新增遊戲預設未上架、沒有新增商戶授權。
- 固定成功情境對既有來源回報可用／明確不可用，並提供一個固定新遊戲；部分失敗只更新取得成功的項目，失敗與未取得項目不動；完全失敗不動遊戲資料。
- 「不可用」是來源回報數，可能同時計入「更新」，不是互斥分類。
- 同供應商重複同步會阻擋。中斷超過 30 秒的本地工作在下次同步時記為失敗，保留原遊戲資料再開始新工作。

## 8. 已知缺口與禁止誤認

- 沒有真實供應商 Adapter、Launch URL、後端權限／帳本防重、成本或正式費用。LocalStorage 是可修改的演示資料，不是安全隔離或多使用者併發保證。
- 同步是固定 Mock 契約，圖片是統一占位；未完成真實分頁拉取、網路重試、供應商類型／圖片與能力認證。新建供應商沒有 Mock 契約時會阻擋同步。
- 商戶授權抽屜本批為必要的唯讀交集展示，沿用現有商戶／線路遊戲配置；新同步遊戲不自動加入舊配置或授權。完整管理者商戶授權編輯流程依後續批次處理，不順帶重做兩端。
- 不推斷歷史歸屬授權、不擴大代理權限；D01–D10 未決項未自行定案。
- 本批不宣稱正式派彩／退款在停用後可成功受理，只證明演示資料未被清除且新啟動被阻擋。
- 獨立驗收待規劃端安排。交驗後維持版本穩定，等待缺失單，不自行開始下一批或直接安排驗收。

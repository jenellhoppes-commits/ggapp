1. 文件範圍與優先規則

文件目的： 本文件為 GGAP 遊戲聚合後台最終版交付規格，供 PM、RD、QA、營運、財務、風控與後端 API 串接使用。 若舊版文件或模組文字與本文件衝突，均以本文件為準。
項目最終規格
產品定位 B2B 遊戲聚合平台後台，支援管理者、代理、商戶三種入口，集中管理供應商、遊戲、商戶、代理、會員、交易、帳務、品質與系統設定。
不包含內容 不描述演示前台、不描述 Demo 視覺畫面、不記錄臨時前端展示方案；僅保留正式系統邏輯與技術規格。
正式帳務幣別 settlement_currency = USDT。平台正式日結、代理應收與平台毛利以 USDT 為準；供應商帳單與付款依合約保留原幣，並同步保存不可變的 USDT 帳務鏡像。
交易／錢包幣別 transaction_currency 是會員錢包、Merchant Callback 與 Provider 即時交易共同使用的真實原幣；display_currency 僅保留作舊版相容別名。正式平台帳務於日結後換算為 USDT。
商戶定位 商戶是真正接入 API、會員、錢包、遊戲權限與投注資料的營運主體；但不是 GGAP 平台正式收款主體。
代理定位 代理是 GGAP 平台正式應收與結算主體。代理底下可有下級代理與商戶，最多三級代理。
供應商定位 供應商是 GGAP 平台自行處理的成本與應付主體，不與代理或商戶形成直接帳務關係。

2. 最終定版核心決策

決策定版內容影響範圍
供應商結算拆分 供應商結算不可依 agent_id 作主維度；多幣別正式維度為 provider_id + provider_currency_id + original_currency + settlement_currency + period，可選加 game_type 或 provider_rate_version。 財務中心、供應商帳務、帳單、資料表、API。
代理結算主體 平台只對代理正式收款。代理結算維度為 agent_id + settlement_currency + period，明細可展開商戶、下級代理、供應商與交易原幣。 代理帳務、代理帳單、下級代理結算、商戶結算。
商戶不作平台正式帳務主體 系統可計算商戶應向代理繳交的金額，但此資訊應歸在代理帳務內的「商戶結算」，不是新增獨立平台商戶帳務。 商戶管理、代理帳務、報表。
代理最多三級 代理層級固定為 L1 / L2 / L3。L1 可新增 L2，L2 可新增 L3，L3 不可再新增下級代理。正式對 GGAP 結算可歸集到 L1 或平台直營代理。 代理管理、資料權限、代理後台、帳務彙總。
費率位置 供應商成本費率放在供應商管理；代理費率放在代理管理；商戶報價放在商戶綁定代理或商戶設定內。三者可依供應商覆寫，未覆寫則使用預設費率。 供應商管理、代理管理、商戶管理、代理帳務、平台毛利。
錢包模式 供應商可依幣別線分別採單一錢包或轉帳錢包，每條線有獨立 API Key、憑證、URL、Provider 廠商 ID 與幣別 ID。商戶側亦保留 Seamless / Transfer Wallet，兩者需以不同欄位記錄。 Wallet Router、交易中心、會員管理、轉點紀錄。
匯率與日結 唯一業務時區為 Asia/Taipei：00:00 關閉 T-1 帳期、00:05 鎖定公告匯率、00:10 執行日結。日結後匯率快照、結算金額與帳單來源鎖定。 匯率管理、日結、報表、帳單、交易快照。
重要修正： 舊文件中若出現「結算維度：agent_id + provider_id + settlement_currency + period」應拆成兩種： 供應商結算使用 provider_id + provider_currency_id + original_currency + settlement_currency + period； 代理結算使用 agent_id + settlement_currency + period，其中 provider_id 只作代理費率套用與明細分析，不代表代理與供應商直接掛鉤。

3.1 商業鏈路

供應商
  ↑  平台自行處理供應商成本、對帳與付款
GGAP 平台
  ↓  平台對代理收款，正式帳務主體為代理
代理 L1
  ↓  可下開 L2 / L3，也可直接綁商戶
代理 L2 / L3
  ↓
商戶
  ↓  真正接入 API、會員、錢包、遊戲與投注
會員

3.2 兩條正式財務線

財務線對象主維度說明
平台 ↔ 供應商 供應商應付 provider_id + provider_currency_id + original_currency + period 平台根據供應商報表、平台 Provider 交易快照、供應商合約與成本費率計算應付供應商金額。
平台 ↔ 代理 代理應收 agent_id + settlement_currency + period 平台根據代理樹底下商戶產生的 GGR、代理費率、調帳與服務費計算代理應收。
代理內部 下級代理結算、商戶結算 parent_agent_id + child_agent_id / merchant_id + period 用於算出 L1 應向下級代理或商戶收多少；屬代理帳務展開，不形成 GGAP 對商戶正式應收。
平台內部 平台毛利 period + provider_id + agent_id + settlement_currency 把代理收入線與供應商成本線拉在一起作管理分析，非正式對外帳單主體。

3.3 利潤來源

來源公式備註
供應商與代理差額 agent_game_charge - provider_payable 例如供應商成本 4%，平台給代理 7%，差額 3% 為主要毛利來源。
匯率服務費 max(base_usdt_amount, 0) × exchange_fee_rate MVP 預設 0.5%。只對正向應收計算，負 GGR 不收取。
調帳與其他成本 platform_adjustment - activity_cost - compensation_cost 活動成本、人工調帳、補償、特殊合約都需進入平台毛利分析。

3.4 核心公式

公式說明
provider_ggr_original = provider_bet_amount - provider_win_amount供應商幣別線原幣 GGR，逐筆交易與對帳都保留原值。
base_settlement_ggr = provider_ggr_original ÷ base_rate依交易帳期公告匯率換算的 USDT 基礎 GGR；匯率方向統一為 1 USDT 可兌換多少原幣。
exchange_service_fee = max(base_settlement_ggr, 0) × exchange_fee_rate匯率服務費獨立計算，不藏入匯率。
agent_game_charge = max(base_settlement_ggr, 0) × agent_rate依供應商對應代理費率計算的遊戲費。
final_agent_receivable = agent_game_charge + exchange_service_fee + agent_adjustmentGGAP 對 L1／平台直營代理的正式應收。
merchant_receivable_to_agent = merchant_game_charge + exchange_service_fee + merchant_adjustment商戶應向所屬代理繳交的金額；服務費沿 L3／L2／L1 原額穿透至 GGAP，不列入代理級差毛利。
provider_payable_usdt = max(provider_cost_base × provider_cost_rate + fixed_fee + adjustment, 0)供應商 USDT 帳務鏡像；原幣帳單依鎖定匯率與 Provider 合約產生，不直接由代理日結產生。
platform_margin = final_agent_receivable - provider_payable + platform_adjustment - activity_cost - compensation_cost平台毛利管理報表；final_agent_receivable 已含匯率服務費，不可再次加計。

6. 模組規格

6.1 商戶管理

項目規格
定位 商戶是真正串接 API、管理會員、錢包模式、遊戲權限與投注資料的營運主體；所有商戶必須綁定代理。
新增流程 基本資料 → 代理歸屬 → API 設定 → 錢包與幣別 → 遊戲權限 → 商戶報價 → 確認送出。
主要欄位 merchant_id、merchant_code、merchant_name、agent_id、agent_path、wallet_mode、display_currencies、settlement_currency、callback_url、ip_whitelist、status。
錢包 支援 Seamless Wallet 與 Transfer Wallet。Transfer Wallet 需有內部帳本與會員轉點紀錄。
商戶報價 綁定代理時帶入代理費率，可依每個供應商設定商戶報價；未指定則使用商戶預設報價加價。匯率服務費是平台費用，不得作為商戶報價備援值。
操作 查看、編輯、啟用、停用、凍結、重置 API Secret、測試 Callback、設定遊戲權限、轉移代理、建立商戶後台帳號、查看操作紀錄。

6.2 代理管理

項目規格
層級最多三級：L1 / L2 / L3。L3 不可新增代理。需防止循環引用與跨樹移動。
正式收款GGAP 正式對代理收款。若 L2 / L3 存在，系統可將正式收款對象歸集到 L1 或平台直營代理，並在代理帳務中展開下級代理結算。
新增流程基本資料 → 上級代理 → 代理層級 → 可用供應商 → 費率設定 → 帳號權限 → 確認。
費率代理建立時設定預設費率；可依每個供應商覆寫。供應商成本只作參考與毛利試算，不代表代理與供應商直接結算。
操作查看、編輯、啟用、停用、凍結、建立下級代理、綁定商戶、設定費率、查看代理帳務、查看下級代理結算、查看商戶結算。

6.3 供應商管理

項目規格
定位供應商是平台成本帳主體，由 GGAP 自行對帳與付款，不直接掛代理或商戶。
新增流程基本資料 → API 設定 → 遊戲同步 → 交易設定 → 幣別語系 → 地區限制 → 成本費率 → 幣別線下注限額方案同步 → 測試環境。
成本費率接入供應商時即可填入成本費率，可依遊戲類型、供應商費率版本、生效時間設定。
負 GGR可設定保留到下期或清零；保留模式必須保存期初、抵扣與期末結轉餘額，正式應付不得小於 0。
維護供應商與遊戲都需支援一次性、每週、每月維護排程；維護期間影響 Launch 與遊戲可見狀態。
下注限額方案每條幣別線各自同步 Provider 提供的投注方案，例如 TWD 50-500、500-5000、5000-10000。方案代碼、上下限、步進、支援遊戲數與版本由 Provider 決定；GGAP 只能勾選開放，不可自行新增或修改數值。
操作查看、編輯、啟用、停用、維護、同步遊戲、測試 API、管理幣別線、於幣別線內勾選下注限額方案、查看供應商帳務、查看操作紀錄。

6.4 遊戲管理與活動指定

模組規格
遊戲管理 管理遊戲主檔、供應商、類型、RTP、支援幣別語系、上下架、維護排程、商戶授權、地區限制。維護支援固定每週或每月。
獎池與活動 活動直接指定適用遊戲與商戶範圍；正式活動成本需能進平台毛利。

6.5 交易中心

模組規格
會員管理會員錢包唯一鍵為 merchant_id + merchant_player_id + transaction_currency。商戶需自行依實際交易幣別切分會員錢包。
注單管理每位會員每一次下注各自建立一筆 bet_record；查詢 Provider Round、注單 ID、交易 ID、會員、商戶、代理、Provider、遊戲、Wallet 模式、原幣金額、日結 USDT 金額、下注限額方案快照與狀態。同一 Round 可有多筆注單。
交易流水保存 Bet、Win、Rollback、Refund、Transfer In、Transfer Out 等交易；必須保存 idempotency key、request/response、trace_id。
Wallet Router依商戶 wallet_mode 分流 Seamless Callback 或 Transfer Wallet Ledger。Provider 不知道商戶錢包模式。
轉點紀錄Transfer Wallet 必須有會員轉入、轉出、投注扣款、派彩加款、回滾與餘額變化紀錄。
補單 / 重送處理 Provider Timeout、Merchant Callback Timeout、狀態不一致、Rollback 找不到原交易等異常。

6.6 品質中心

模組規格
風控管理設定商戶、會員、遊戲、金額、頻率、IP、設備、異常贏分、負餘額等規則。
監控告警監控 Launch、Provider、Wallet Callback、交易失敗率、延遲、匯率異常、日結失敗、批次失敗。
操作紀錄所有高風險操作需記錄 operator、role、portal、module、before/after、reason、ip、trace_id。

6.7 系統管理與開發者中心

模組規格
開發者中心放置 API 文件、簽名規則、Callback 範例、錯誤碼、Sandbox 測試、Callback 測試、IP 白名單與 Secret 重置入口。
系統設定管理時區、幣別、匯率來源、告警門檻、交易重試、日結時間、資料保留、匯出限制。
人員與權限支援功能權限、資料權限、角色、職級、2FA、登入安全與審核流程。

7. 費率與商戶報價規格

7.1 費率層級

層級設定位置用途可否依供應商覆寫
供應商成本費率 供應商管理 平台計算供應商成本與平台毛利。 可，並可依遊戲類型或版本。
代理費率 代理管理 平台向代理收款的費率。新增代理時即可決定給此代理的價格。 可，未指定則使用代理預設費率。
商戶報價 商戶管理 / 綁定代理 代理要向商戶收多少。系統只作代理帳務內的商戶結算，不形成平台對商戶應收。 可，未指定則使用商戶預設報價加價；不得使用匯率服務費率代替商戶報價。
匯率服務費率 匯率管理 / 代理設定 交易原幣換算 USDT 時另計的結算服務費，MVP 預設 0.5%，不可藏入匯率。 可依代理或合約調整。

8. 財務中心規格

8.1 財務中心模組

模組主體主要內容
供應商帳務 供應商 供應商成本、供應商對帳、供應商應付帳單、供應商付款紀錄。不得以代理或商戶作正式帳務主體。
代理帳務 代理 代理應收、日結明細、帳單、收款紀錄、帳務差異、下級代理結算、商戶結算。
平台毛利 平台內部 代理最終應收（已含匯率服務費）、供應商應付、平台調整、活動與補償成本、毛利試算。
匯率管理 幣別 幣別設定、每日公告匯率、交易匯率與服務費快照、匯率異常告警。服務費政策由系統設定或代理合約維護，匯率管理不可直接修改。
帳單管理 代理 / 供應商 代理應收帳單、供應商應付帳單。使用 target_type + target_id 避免主體混淆。
調帳紀錄 帳期 / 對象 所有人工補正、費率修正、差異處理與帳務調整，需保留原因與審核紀錄。

8.2 代理帳務內部頁籤

頁籤內容
基本資料帳期、正式收款代理、代理層級、結算幣別、狀態、應收摘要。
日結明細依日期、供應商、商戶、交易原幣展開，用於套用不同代理費率。
帳單代理應收帳單、付款狀態、付款證明、核銷狀態。
收款紀錄代理付款、入帳、沖帳與未收金額。
帳務差異代理確認差異、調帳、補單、Carry Forward。
下級代理結算計算 L1 對 L2、L2 對 L3 的應收或分潤，不形成供應商帳。
商戶結算計算代理應向商戶收多少，作為代理報表與帳務依據。
操作紀錄帳務產生、確認、調整、開帳、鎖帳、收款與匯出紀錄。

11. 批次、冪等與一致性

11.1 每日關帳、匯率鎖定與日結批次

  1. 每日 Asia/Taipei 00:00 關帳、00:05 鎖定公告匯率、00:10 啟動日結；帳期為 T-1 00:00:00 至 23:59:59。批次鎖定後收到的延遲 Callback 不得自動重開，需保留原交易日並建立次期調整批次。
  2. 讀取所有已發生交易的 provider_currency，先取得並鎖定該交易日公告匯率。
  3. 呼叫第三方匯率 API，產生 exchange_rate_daily；同批次不可混用不同匯率版本。
  4. 若 API 失敗，重試；仍失敗則沿用上一筆有效匯率並告警。
  5. 波動超過門檻需進入待確認，不可自動覆蓋已鎖定帳期。

11.2 每日日結批次

  1. 匯率鎖定後立即執行日結；每筆交易由 Provider 原幣換算成 USDT，寫入 settlement_batch_id 與 settlement_status。
  2. 建立 daily_trade_summary，依代理、商戶、供應商、Provider 幣別 ID 與原幣彙總交易。
  3. 產生 agent_settlement，作為代理應收與下級代理 / 商戶結算來源。
  4. 產生或更新平台毛利分析資料。
  5. 供應商正式帳單不可直接由代理日結來源產生，需由 provider_settlement 根據 Provider 交易快照、供應商報表與供應商費率計算。
  6. 日結完成後鎖定 batch，後續差異需走調帳或下一期修正。

11.3 冪等規範

場景唯一鍵規則
Provider 交易provider_currency_connection_id + provider_transaction_id不同幣別線可使用相同 Provider Tx 格式；重送時返回原結果，不重複扣加款。
逐筆注單provider_currency_connection_id + provider_bet_id一位會員每一次下注都建立獨立 bet_record；round_id 只作關聯與回合查詢，不作唯一鍵。

Transfer Walletaccount_id + idempotency_key餘額更新需使用交易鎖或樂觀鎖。
日結批次batch_id + period + dimension同一帳期同一維度不得產生多筆生效結算。
調帳adjustment_id不得直接改歷史交易，只能新增調帳、補單或 reversal。

12. 安全、稽核與驗收

12.1 安全規格

項目規格
API 安全HMAC-SHA256 或 RSA 簽名、時間戳、防重放、IP 白名單、API Key / Secret。
敏感資料Password、API Secret、2FA Secret、Token 不可明文儲存或寫入 Log，只可遮罩或重置。
高風險操作匯率覆蓋、費率異動、補單、重送、調帳、鎖帳、重置 Secret 需輸入原因，可要求 2FA 或審核。
資料權限MASTER 全域；AGENT 僅代理樹；MERCHANT 僅自身商戶。後端必須以 token claims 強制限制。
金額精度DB 使用 DECIMAL 或整數最小單位；API 金額建議以字串傳輸；不可用 float / double 處理財務。

12.2 驗收清單

類別驗收項目
帳務模型供應商帳務未掛代理或商戶作為正式主體；代理帳務包含下級代理與商戶結算展開。
代理層級L1 / L2 / L3 正確限制，L3 不可新增代理，代理樹資料不可跨權限查詢。
商戶新增商戶必須綁定代理；代理入口只能在自身代理樹新增商戶；商戶報價可依供應商設定。
供應商管理供應商接入時可設定成本費率與負 GGR；每條幣別線可獨立維護 Provider 幣別 ID、廠商 ID、API Key、憑證、URL、錢包種類、金額精度與狀態。下注限額方案由 Provider 依幣別線提供，GGAP 只勾選允許下放的方案。
交易流水每筆交易保存 bet_id、round_id、provider_currency_connection_id、provider_currency、provider_amount、settlement_currency、settlement_amount、settlement_batch_id 與不可變 Payload。
注單明細每位會員每一次下注各自產生一筆 bet_record；同一 Round 可有多個 bet_id，列表、匯出與 API 不得只回傳 Round 彙總。每筆需保存生效的 Provider 幣別線下注限額方案、版本與上下限快照。
Transfer WalletTransfer In / Out、Bet、Win、Rollback 均產生 ledger，before / after balance 正確。
匯率批次00:00 取得公告匯率、00:05 鎖定交易日快照；異常重試與告警；日結不因後續匯率更新重算。
日結批次00:00 關帳、00:05 鎖匯率、00:10 日結，逐筆將 Provider 原幣換算為 USDT；供應商原幣帳單與付款獨立保存並建立 USDT 鏡像。
API 串接所有列表支援分頁、排序、篩選；所有回應包含 code、message、data、trace_id。
稽核所有費率、匯率、補單、調帳、鎖帳與 Secret 操作具 before/after、reason、operator、trace_id。
最終結論： GGAP 正式模型為「供應商成本帳」與「代理收入帳」完全拆分； 商戶是真正接入與營運主體，但商戶應收只作代理帳務展開； 平台毛利才把代理最終應收（已含匯率服務費）、供應商應付、平台調整與其他成本合併分析。

## 3. 不可被舊文件覆蓋的最新方向

1. Provider 即時交易走 Provider 幣別線原幣，不強制即時換成 USDT。
2. 不固定每日 T-1 正式日結；依商戶與 Provider 各自合約帳期，結算時鎖匯並換成結算幣別。
3. 每位會員每次下注建立一筆獨立注單；Round 只作關聯。
4. 移除所有端限紅／單槍控制；保留歷史及 Provider 原始交易資訊。
5. 遊戲分組、獎池活動、品質中心前期不做；監控、錯誤紀錄及稽核不可一併刪除。
6. Provider 應付、商戶應收與代理佣金為三條獨立財務線。
7. 商戶是正式客戶；代理是推廣與佣金角色，不沿用 Root Agent 應收。
8. 商戶每個幣別一條線，只有已有可用 Provider 同幣別能力才能提供。
9. 內容管理下分為供應商管理、遊戲管理、試玩管理；試玩維持獨立頁，不併遊戲／供應商頁籤，共用線路與遊戲能力。既有網址保留正確相容性。標籤只作遊戲屬性。
10. 商戶報價、Provider 成本與代理佣金分開，佣金基礎與多層分佣仍待決。
11. 五區塊 MVP 不新增換匯收費；不得沿用舊版 0.5% 或自動加收服務費。未來如另經使用者定案，須明確收費基礎、分項與防重複計入規則，不能由舊文件推定已批准。
12. 三入口依全域、被授權推廣商戶及自身商戶範圍隔離，不因舊代理樹自動開放明細。
13. 試玩與正式資金隔離；無 Provider Demo／Sandbox 能力不得偽裝免費試玩。
14. 已鎖定匯率、費率、交易、結算及帳單不得覆寫；所有畫面以繁體中文為主。
15. 商戶 Wallet 模式維持商戶層級、各幣別線繼承；供應商 Wallet 能力另行驗證。
16. 保留既有代理階層與歸屬資料，不擅自刪除、不另造新的多層分潤公式。
17. 第一階段最多做到對帳結算，不含自動收付款與完整財務 ERP。
18. 管理者側欄只保留商務管理、內容管理、交易中心、財務中心、系統管理五區塊；商務管理下唯一報表查詢頁提供運營、代理、商戶、遊戲四分頁，不另設總覽或多層報表樹，也不並行分散式完整報表。
19. 交易中心只保留會員與錢包、注單管理、交易流水；局號併注單，轉點與只讀查單併流水／詳情，不設補單送單或人工補款重送流程。

## 4. 規格變更流程

每項新需求依下列順序處理：

1. 提交需求：說明問題、目標角色、期望結果與範例。
2. 影響分析：列出受影響模組、資料、API、財務、權限、報表與歷史相容性。
3. 規格確認：先更新 PRD／系統規格，標記新增、修改、刪除與暫緩。
4. 驗收定義：建立可測試的 Given／When／Then 或明確結果。
5. 實作：規格確認後才修改演示與程式。
6. 驗證：執行業務規則、權限、RWD、欄位、互動及建置檢查。
7. 發布：確認版本、提交、部署並更新變更紀錄。

## 6. 版本規則

- Patch：文字澄清、畫面微調，不改業務結果。
- Minor：新增模組、欄位、流程或可向下相容的 API。
- Major：改變帳務主體、幣別策略、代理層級、唯一鍵、日結方式或不相容 API。
- 每次變更需記錄日期、需求編號、受影響模組與遷移方式。

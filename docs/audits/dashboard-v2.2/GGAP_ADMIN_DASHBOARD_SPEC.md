# GGAP 管理者儀表板規格

版本：Dashboard v1.0（依 GGAP v2.2 與目前本機演示整理）  
範圍：管理者總後台 `/dashboard`  
狀態：規格整理，尚未實作

## 1. 產品目的

儀表板用來回答三件事：

1. 指定日期與原幣別下，平台目前發生多少營運交易。
2. 供應商、商戶線路、遊戲同步與每日匯率是否可用。
3. 管理者現在最需要處理哪些串接、交易或對帳工作。

儀表板不是另一套完整報表，也不是風控中心或財務總帳。完整統計與明細仍導向「報表查詢」、交易中心與對帳頁面。

## 2. 現況稽核

### 2.1 無資料狀態

![目前儀表板無資料狀態](./01-dashboard-top.png)

- 日期、原幣別、平台時區及資料更新時間清楚。
- 預設查詢日期沒有演示資料時，四項統計直接顯示 0，無法分辨「完整資料確實為 0」或「該日期沒有樣本來源」。
- 篩選卡占據首屏大部分高度，使用者進入後看不到待處理工作。

### 2.2 有資料狀態

![目前儀表板有資料狀態](./02-dashboard-sample.png)

- 四項原幣營運指標與報表口徑一致，且沒有混合幣別。
- 畫面只提供報表入口，沒有供應商、線路、遊戲同步、對帳差異、匯率及維護排程摘要。
- 現況更接近「營運報表捷徑」，未完成總後台儀表板的工作入口功能。

## 3. 內容架構

頁面由上至下固定為六區：

```text
[營運儀表板] [資料更新時間] [重新整理]
[日期範圍] [原幣別] [更多條件] [查詢] [重置]
[下注筆數] [投注人數] [投注金額] [派彩金額]
[待處理工作                         ] [平台狀態]
[聚合器資源摘要：供應商／線路／商戶／遊戲]
[最近資料更新與操作紀錄]
```

### 3.1 頁首

- 標題：`營運儀表板`。
- 說明：`查看平台營運、串接狀態與待處理工作。`
- 顯示目前環境、平台時區、資料版本與最後更新時間。
- 操作只保留「重新整理」；儀表板不提供獨立匯出，匯出導向報表或對應列表。
- 演示環境保留全站既有黃色標示，不在各區重複大段開發說明。

### 3.2 共用查詢範圍

| 欄位 | 規則 |
| --- | --- |
| 日期範圍 | 必填；以平台時區計算。正式預設今日，演示預設固定樣本日期，不能以無樣本日期顯示假 0 |
| 原幣別 | 必填且單選；禁止跨幣別加總 |
| 商戶 | 選填，限授權範圍 |
| 供應商 | 選填，限授權範圍 |
| 更多條件 | 收合商戶與供應商，顯示已選擇數量 |

- 修改條件不立即改數字，按「查詢」或 Enter 後才套用。
- 查詢更新全部區塊並共用同一資料版本；不能讓 KPI 與待辦使用不同時間點。
- URL 保存非敏感查詢條件；重新整理與返回仍可還原。
- 「重置」清除商戶、供應商與排序，保留合法原幣別，回預設日期。

### 3.3 營運 KPI

第一版固定四項，完全沿用已完成的四報表來源：

| 指標 | 定義 | 點擊目的地 |
| --- | --- | --- |
| 下注筆數 | 已成功受理的原始下注唯一識別數 | 注單管理，帶入同一查詢條件 |
| 投注人數 | 環境＋商戶＋會員識別去重 | 會員與錢包，帶入期間與幣別 |
| 投注金額 | 去重下注的原幣金額 | 營運報表 |
| 派彩金額 | 已成功且關聯明確的原幣派彩 | 營運報表 |

- 金額顯示千分位、幣別與幣別精度。
- 缺來源顯示「資料待確認」，不能以 0 代替。
- 卡片整體可點擊，也必須有可見焦點與明確可及名稱。
- 本版不顯示 GGR、RTP、ROI、成本、佣金、毛利或 USDT 估值。GGR 待 D01 正式口徑確認後另行決定。

### 3.4 待處理工作

只顯示有正式資料來源且使用者有權限的項目，依嚴重程度及期限排序：

| 工作 | 數量來源 | 點擊目的地 |
| --- | --- | --- |
| 供應商線路待完成 | 草稿、測試中、維護且有待辦原因的供應商線 | 供應商管理 |
| 遊戲同步需處理 | 部分失敗或失敗的同步工作 | 遊戲管理／同步紀錄 |
| 商戶串接待完成 | 尚未通過正式啟用條件的商戶線 | 商戶管理 |
| 待處理交易 | 交易技術狀態需人工確認，非風控判斷 | 注單管理或交易流水 |
| 對帳差異 | 尚未完成差異處理的對帳項目 | 差異處理 |
| 待確認對帳 | 已具備資料、等待財務確認的供應商／商戶／代理對帳 | 對應對帳頁 |
| 今日匯率未完成 | 今日應記錄幣別尚未取得或鎖定 | 匯率管理 |
| 即將維護 | 24 小時內的有效維護排程 | 維護設定 |

- 數量未知顯示「尚未接入」，不顯示 0。
- 無權限項目整張隱藏，不先把敏感數量送到瀏覽器。
- 每列顯示項目、數量、最早期限或原因；不使用只有顏色的嚴重程度。
- 沒有待辦時顯示「目前沒有待處理工作」，保留各模組入口。

### 3.5 平台狀態

右側摘要只顯示會影響營運判斷的最新狀態：

- 交易資料截止時間。
- 最近一次遊戲同步狀態與完成時間。
- 今日匯率取得／鎖定狀態。
- 下一個維護排程。
- 正式環境可用性不得由前端自行推算；來源未接入時標示未驗證。

### 3.6 聚合器資源摘要

| 指標 | 口徑 | 點擊目的地 |
| --- | --- | --- |
| 啟用供應商 | 供應商狀態為啟用 | 供應商管理 |
| 可用供應商線路 | 正式環境、線路啟用且通過一般串接條件；不要求支援試玩 | 供應商管理的線路篩選 |
| 啟用商戶 | 商戶狀態為啟用 | 商戶管理 |
| 啟用商戶線路 | 商戶線狀態啟用且具有至少一個授權交集 | 商戶管理的線路篩選 |
| 可用遊戲 | 遊戲、供應商線及授權交集皆可用 | 遊戲管理 |

資源摘要不受日期範圍影響，但受環境與資料權限影響。畫面須標示「目前狀態」，避免被誤解為期間統計。

### 3.7 最近更新

- 最多顯示最近 5 筆與營運有關的操作：供應商狀態、線路啟停、遊戲同步、商戶線啟用、對帳確認及匯率鎖定。
- 顯示時間、對象、操作、結果及操作人。
- 憑證內容、API Key、會員資料與原始 payload 不得出現在儀表板。
- 完整內容導向操作紀錄，不在儀表板另做搜尋與分頁。

## 4. 暫不加入

- 風控告警、受限會員、RTP 調控、遊戲限紅與品質中心入口。
- 遊戲或商戶排行榜。
- 由固定權重或隨機數生成的七日趨勢。
- 未確認公式的 GGR、成本、代理佣金、平台毛利與預估結算金額。
- 跨幣別總額及自動 USDT 估值。
- 直接在儀表板執行結算確認、啟停線路或重設憑證。

待後端提供真實逐日聚合來源後，可新增同原幣別的下注與派彩趨勢；不得先以假比例拆分總額。

## 5. UI 規格

### 5.1 桌面 >= 1200px

- 使用 12 欄網格；內容最大寬度沿用現有後台。
- 篩選列單行，進階條件收合。
- 四個 KPI 同列。
- 待處理工作占 8 欄，平台狀態占 4 欄。
- 聚合器摘要同列 5 項；最近更新使用全寬表格。
- 主區塊採平面分隔，只在需形成一組可點擊資訊時使用卡片。

### 5.2 平板 768–1199px

- KPI 兩欄兩列。
- 待處理與平台狀態改為上下排列。
- 聚合器摘要兩欄並自動換行。
- 篩選欄規則換行，查詢與重置保持一組。

### 5.3 手機 < 768px

- 篩選表單單欄；日期控制不可超出內容寬度。
- KPI 兩欄；若 360px 或 200% 縮放無法完整顯示金額則改單欄。
- 待辦每列使用「標題＋原因／期限＋數量＋箭頭」，觸控範圍至少 44px。
- 最近更新改為摘要列，不固定右側操作欄；寬表只在表格區水平捲動。
- 查詢與重置並排，不能讓單一重置按鈕獨占整行。

## 6. UX 與狀態

| 狀態 | 畫面行為 |
| --- | --- |
| 初次進入 | 顯示骨架，取得授權、可用幣別及預設條件後再查詢 |
| 載入中 | 保留區塊尺寸，不先把舊條件的 0 顯示成新結果 |
| 完整資料為 0 | KPI 顯示 0，並寫明「本範圍無交易」 |
| 缺資料來源 | 受影響區塊顯示「資料待確認」及原因，其他可驗證區塊正常顯示 |
| 查詢失敗 | 保留已輸入條件，顯示重試與 Trace ID；不拿舊結果冒充新查詢 |
| 部分模組失敗 | 只在該區顯示錯誤，不讓整頁空白 |
| 無權限 | 隱藏無權限區塊並重新排版；不顯示敏感數量後再遮罩 |
| 無待辦 | 顯示完成狀態與各模組入口，不製造假數量 |

- 重新整理必須防止重複請求，完成後顯示更新時間。
- 點擊 KPI 或待辦時帶入已套用條件；目標頁不支援的條件不得硬塞。
- 返回儀表板保留查詢與捲動位置。
- 鍵盤操作依頁首、篩選、KPI、待辦、狀態、最近更新順序；焦點清楚可見。
- 狀態必須同時使用文字與圖示，不能只靠紅、綠、黃。

## 7. 資料契約

建議單一 Dashboard API 回傳共同版本與分區狀態：

```text
query: environment, timezone, from, to, currency, merchant_id?, provider_id?
response:
  version, cutoff_at, timezone, currency
  operation_summary
  pending_items[]
  platform_status
  resource_summary
  recent_actions[]
  section_statuses[]
```

- 所有日期型營運值共用 `version` 與 `cutoff_at`。
- 資源摘要明確標示為目前狀態，不併入日期型查詢合計。
- 各分區回傳 `ok / incomplete / unavailable` 與原因，避免前端把缺來源轉成 0。
- 後端依角色與資料範圍裁切；前端不接收無權限區塊的敏感資料。

## 8. 驗收案例

1. 預設日期沒有演示來源時顯示無資料，不顯示四個假 0。
2. 同一查詢的 KPI、導向報表與注單明細使用相同版本、幣別與授權範圍。
3. 不同原幣別分開顯示，不提供混合總額。
4. 缺派彩來源時只將派彩標示待確認，不影響可驗證的下注筆數。
5. 待辦數量與對應列表相同；無權限角色不收到該數量。
6. 不支援試玩的供應商線仍可計入一般可用線路，不混用試玩資格。
7. 商戶具有 TWD 線但沒有供應商授權交集時，不計入可用商戶線。
8. 今日匯率未鎖定時顯示待處理，不以昨日匯率假裝今日完成。
9. 重新整理期間保持布局，較舊回應不能覆蓋較新的查詢。
10. KPI、待辦與資源摘要皆可用鍵盤開啟，焦點順序合理。
11. 360、390、768、1280、1440、1920px 與 200% 縮放不造成頁面本體水平溢出。
12. 正式驗收逐項標示「模擬通過／正式通過／未驗證」，前端演示不視為後端正式通過。

## 9. 建議開發順序

1. 建立儀表板專用頁，不再直接嵌入報表查詢元件。
2. 共用已完成的四報表查詢範圍與四項營運 KPI。
3. 串接供應商、遊戲同步、商戶線、對帳、匯率與維護的待辦摘要。
4. 補聚合器資源摘要、平台狀態與最近操作。
5. 完成 URL 還原、權限裁切、載入／空白／部分失敗狀態。
6. 完成多尺寸、鍵盤、數字口徑與跨頁導向驗收。
